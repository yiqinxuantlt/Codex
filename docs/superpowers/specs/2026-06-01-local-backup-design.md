# 本地数据同步备份设计

## 背景

当前读书笔记随机回顾应用已经支持本地 IndexedDB、局域网同步、导入字体、主题切换、句子库管理、阅读记录、PWA 和 Android APK。数据主体分布在四类记录中：

- `notes`：句子库。
- `settings`：显示、主题和字体设置。
- `fonts`：用户导入的本地字体。
- `readingEvents`：每条句子的停留记录。

现有代码已经有 `loadLocalSnapshot()`，可以生成包含以上数据的完整快照；局域网同步服务也使用相同的完整状态结构保存到 `sync-data.json`。本设计在这个基础上增加“备份与恢复中心”，并补充几项高价值的数据管理能力。

## 目标

- 支持手动导出完整备份文件，方便用户在电脑、手机、APK、浏览器之间迁移和恢复数据。
- 支持导入完整备份文件，并提供“合并导入”和“完全覆盖”两种恢复方式。
- 增加本地自动快照，误删、误导入、误覆盖后可以从最近快照恢复。
- 在支持 File System Access API 的桌面浏览器中，允许绑定一个本地备份文件并一键写入。
- 在局域网同步服务中增加服务端自动备份，让 `sync-data.json` 每次被覆盖前有本地备份。
- 增加数据体检、阅读记录导出、收藏句子等低风险实用功能。
- 保持当前极简、温和、纸张质感的界面风格。
- 不破坏 IndexedDB、局域网同步、PWA 和 APK 的现有逻辑。

## 非目标

- 不做公网云同步、账号系统、登录授权或第三方云盘集成。
- 不把个人数据上传到 GitHub 或任何外部服务。
- 不重写项目为 React、Vue 或多页面工程。
- 不改变现有 CSV 导入、随机回顾、左右滑动、阅读停留记录的核心行为。
- 不在每次切换句子时创建完整本地快照，避免阅读记录频繁追加时产生大量备份。

## 推荐方案

采用“完整快照 + 本地备份中心 + 桌面增强备份 + 服务端安全备份”的混合方案。

基础能力面向所有环境：

- 手机浏览器、桌面浏览器、GitHub Pages、APK 都支持手动导出和导入 JSON。
- IndexedDB 中新增 `backups` store，保存最近 10 份自动快照。
- 清空句子库、CSV 覆盖导入、备份覆盖恢复等高风险操作前自动创建快照。

桌面增强能力按浏览器能力启用：

- 如果支持 File System Access API，显示“绑定备份文件”和“写入绑定文件”。
- 如果不支持，则隐藏绑定入口，保留普通下载式导出。

局域网同步增强能力由 `sync-server.js` 提供：

- 每次写入 `sync-data.json` 前，把旧状态保存到本地 `backups/` 目录。
- 保留最近 10 份服务端备份。
- 这些备份仅保存在用户电脑本地，并继续被 `.gitignore` 排除。

## 数据结构

### 备份文件格式

导出的 JSON 文件使用一个外层信封，方便版本识别：

```json
{
  "type": "reading-note-reviewer-backup",
  "backupVersion": 1,
  "exportedAt": "2026-06-01T12:00:00.000Z",
  "sourceMode": "local",
  "summary": {
    "notes": 120,
    "fonts": 2,
    "readingEvents": 800
  },
  "data": {
    "schemaVersion": 1,
    "updatedAt": "2026-06-01T12:00:00.000Z",
    "notes": [],
    "settings": {},
    "fonts": [],
    "readingEvents": [],
    "meta": {
      "createdAt": "2026-06-01T12:00:00.000Z",
      "lastWriteSource": "manual-export"
    }
  }
}
```

导入时同时兼容两种输入：

- 新的备份信封格式。
- 现有局域网同步状态格式，也就是直接包含 `notes/settings/fonts/readingEvents` 的对象。

### IndexedDB 扩展

把数据库版本从 `2` 升级到 `3`，新增对象仓库：

```text
backups
```

字段设计：

```json
{
  "id": "backup_...",
  "kind": "auto",
  "source": "csv-import-before-replace",
  "createdAt": "2026-06-01T12:00:00.000Z",
  "summary": {
    "notes": 120,
    "fonts": 2,
    "readingEvents": 800
  },
  "data": {}
}
```

索引：

- `createdAt`
- `kind`

本地快照只保存在当前浏览器，不参与局域网同步，避免不同设备互相复制大量历史备份。

## 备份中心 UI

设置首页新增“备份与恢复”入口，进入后展示四块内容。

### 数据概览

显示：

- 句子数量。
- 收藏数量。
- 本地字体数量。
- 阅读记录数量。
- 最近本地快照时间。
- 当前存储模式：本地、局域网同步或手动同步地址。

### 手动备份

提供按钮：

- “导出完整备份”：下载 JSON 文件。
- “导入备份文件”：选择 `.json` 文件。
- “导出阅读记录 CSV”：只导出阅读事件汇总，方便长期统计。

导入备份文件后显示摘要：

- 文件中的句子数量。
- 字体数量。
- 阅读记录数量。
- 导出时间。

用户选择：

- “合并导入”：按 `id` 合并句子、字体和阅读记录；设置字段采用备份中的兼容字段覆盖当前字段。
- “完全覆盖”：先自动创建当前快照，再用备份文件替换当前四类数据。

### 本地快照

展示最近 10 份快照列表：

- 创建时间。
- 来源，例如 CSV 导入前、清空前、手动快照、覆盖恢复前。
- 句子数、字体数、阅读记录数。

每条快照提供：

- “恢复”：默认完全恢复该快照，恢复前再次保存当前状态为快照。
- “删除”：只删除这条快照。

### 桌面备份文件

如果支持 File System Access API：

- 显示“绑定备份文件”。
- 显示“写入绑定文件”。
- 显示最近一次写入结果。

绑定后，用户每次点击“写入绑定文件”会把完整备份写入同一个本地文件。自动写入只在页面打开且浏览器仍有文件权限时尝试；如果权限过期，则提示重新绑定。

如果不支持：

- 显示简短说明：“当前环境不支持绑定本地文件，可使用导出完整备份。”

## 恢复规则

恢复前先提交当前阅读停留事件，避免最后一条阅读记录丢失。

合并导入：

- `notes`：按 `id` 合并；同一 `id` 取 `updatedAt` 较新的记录。
- `fonts`：按 `id` 合并；同一 `id` 取较新的记录。
- `readingEvents`：按 `id` 去重后合并。
- `settings`：用备份中的已知字段覆盖当前设置，并通过现有 `sanitizeDisplaySettings()` 清洗。

完全覆盖：

- 本地模式下替换 IndexedDB 中的 `notes`、`fonts`、`readingEvents` 和显示设置。
- 局域网同步模式下调用现有完整状态接口覆盖远端主库。
- 覆盖后重新注册字体、应用主题、刷新句子库、刷新阅读记录图表，并回到可用的阅读状态。

导入失败时：

- 不写入任何数据。
- 显示原因，例如文件不是有效备份、JSON 解析失败、缺少可恢复字段。
- 保留当前数据。

## 自动快照策略

以下操作前创建快照：

- CSV 导入并覆盖句子库。
- 清空句子库。
- 完全覆盖恢复备份。
- 从快照恢复。
- 数据体检中由用户确认的大批量清理。

以下操作后创建节流快照：

- 新增、编辑、删除句子。
- 导入或删除字体。
- 主题、字号、行距、字体设置改变。

节流规则：

- 同类普通修改 2 分钟内只创建一份快照。
- 阅读停留事件不会每条都创建完整快照；如果用户连续阅读很久，最多每 30 分钟创建一份阅读记录快照。
- 始终保留最近 10 份，超出后删除最旧快照。

## 服务端备份

`sync-server.js` 增加本地服务端备份：

- 创建 `backups/` 目录。
- 每次 `saveState()` 覆盖 `sync-data.json` 前，如果旧文件存在且有效，先复制一份到 `backups/sync-data-YYYYMMDD-HHmmss.json`。
- 保留最近 10 份服务端备份。
- 服务器启动时输出备份目录提示。

这个能力保护电脑端主库，不影响手机和浏览器内的普通使用。

## 数据体检

备份中心加入“数据体检”小节，计算并显示：

- 空内容笔记数量。
- 疑似重复笔记数量。
- 没有对应句子的阅读记录数量。
- 过大的字体文件数量。

第一版只提示和展示，不自动删除。对于重复笔记，提供“查看重复项”列表；用户仍通过句子库手动编辑或删除，避免误删。

重复判断规则：

- 去掉首尾空白。
- 合并连续空白字符。
- 以 `content + book + author` 作为重复键。

## 收藏句子

`notes` 增加可选字段：

```json
{
  "favorite": false
}
```

兼容旧数据：缺少该字段时按 `false` 处理。

UI 行为：

- 阅读卡片右上角显示一个低调收藏按钮。
- 句子库列表中也可以切换收藏。
- 设置首页显示收藏数量。
- 随机回顾区域提供“全部 / 收藏”轻量筛选；如果收藏为空，自动回到全部并提示。

这个功能不改变原始 CSV 字段，也不影响已有笔记。

## 阅读记录导出

在备份中心提供“导出阅读记录 CSV”。

导出字段：

- `noteId`
- `book`
- `author`
- `content`
- `startedAt`
- `endedAt`
- `durationMs`
- `durationText`
- `dateKey`
- `source`

CSV 使用 PapaParse 的 `unparse` 能力生成，避免逗号、换行和中文内容破坏格式。

## 错误处理

- 浏览器不支持 IndexedDB：沿用现有错误提示，备份中心不可用。
- 导入 JSON 解析失败：提示“备份文件格式无法识别”。
- 导入数据为空：提示“没有可恢复的数据”。
- 本地字体过大导致备份文件很大：数据体检提示字体数量和大文件风险。
- File System Access 权限失效：提示重新绑定备份文件。
- 局域网同步保存失败：保持当前内存数据，不显示恢复成功。
- 服务端备份失败：控制台输出警告，但不阻断正常保存 `sync-data.json`。

## 风险与缓解

- 备份文件可能包含用户导入字体，体积较大。
  - 缓解：数据体检显示字体数量和大文件风险；导出仍由用户主动触发。
- 恢复覆盖是高风险操作。
  - 缓解：覆盖前自动保存当前快照，并二次确认。
- File System Access API 在手机和部分浏览器不可用。
  - 缓解：把它作为增强功能，普通导出导入始终可用。
- 收藏字段改变 `notes` 数据形状。
  - 缓解：字段可选，旧数据通过 `createNote()` 默认补 `false`。
- 服务端备份可能累积占用磁盘。
  - 缓解：只保留最近 10 份，并排除 Git 跟踪。
