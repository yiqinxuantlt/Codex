# 局域网同步设计

## 背景

当前读书笔记回顾应用是一个本地单页网页：`index.html` 使用 IndexedDB 保存句子库、显示设置、本地字体和阅读记录。这个架构适合单设备离线使用，但电脑和手机各自拥有独立浏览器存储，直接打开 `file://.../index.html` 时无法自动共享数据。

用户希望移动端和电脑端同步，并已确认采用“同一局域网同步”。本设计将同步能力作为可选增强：默认仍保留本地离线模式；当电脑启动本地同步服务后，电脑和手机访问同一个局域网地址，共用同一份数据。

## 目标

- 让电脑端和手机端在同一 Wi-Fi / 局域网内共享句子库、阅读记录、主题设置、字体设置和导入字体。
- 保留现有 `file://` 打开方式，继续支持完全离线、本机 IndexedDB 使用。
- 增加一个轻量本地同步服务，由电脑作为主机保存数据，手机通过浏览器访问。
- 在网页里清楚显示当前是“本地模式”还是“局域网同步模式”。
- 支持从现有本地数据迁移到局域网主库，避免用户重复导入 CSV。
- 实现方式尽量轻量，不引入大型框架或复杂登录系统。

## 非目标

- 不做公网同步、云端账号、多设备远程访问或跨网络同步。
- 不做复杂多人实时协作；同一局域网内允许多设备使用，但冲突处理以简单可靠为主。
- 不将用户数据上传到第三方服务。
- 不强制用户始终启动同步服务；没有同步服务时，应用仍能按现在的方式本地运行。
- 不把项目改造成多页面工程或重型前端项目。

## 推荐方案

采用“本地 Node.js 同步服务 + 现有单页应用适配”的方案。

电脑端运行一个本地服务，例如：

```text
http://电脑局域网IP:8787/
```

服务负责两件事：

- 提供 `index.html`，让电脑和手机打开的是同一个应用入口。
- 提供 `/api/...` 接口，把句子库、设置、字体和阅读记录写入电脑本地的 `sync-data.json`。

网页根据打开方式自动选择存储模式：

- `file://.../index.html`：继续使用当前 IndexedDB，本地离线模式。
- `http://localhost:8787/` 或 `http://电脑IP:8787/`：进入局域网同步模式，通过 API 读写电脑上的共享数据。

这个方案比“手动导出导入文件”更顺滑，也比“浏览器点对点同步”更稳。它的代价是需要电脑启动一个小服务，且手机必须和电脑在同一局域网。

## 文件设计

新增文件：

- `sync-server.js`：本地同步服务，使用 Node.js 原生 `http`、`fs`、`path` 模块实现。
- `sync-data.json`：同步数据文件，由服务自动创建和维护。
- `start-sync.bat`：Windows 启动脚本，双击后启动同步服务，并显示可访问地址。

继续使用：

- `index.html`：主应用仍保持单页结构，新增同步模式检测、远程存储适配、同步状态 UI 和迁移入口。

不新增构建流程，不要求安装 npm 依赖。

## 数据结构

服务端 `sync-data.json` 使用一个统一状态文件：

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-05-29T12:00:00.000Z",
  "notes": [],
  "settings": {},
  "fonts": [],
  "readingEvents": [],
  "meta": {
    "createdAt": "2026-05-29T12:00:00.000Z",
    "lastWriteSource": "device_xxx"
  }
}
```

字段延续现有 IndexedDB 结构：

- `notes`：句子库，每条包含 `id`、`content`、`book`、`author`、`chapter`、`remark`、`createdAt`、`updatedAt`。
- `settings`：显示设置、主题、字体、字号、行高等。
- `fonts`：本地导入字体，继续保存 `dataUrl`、字体名、文件类型、创建时间。
- `readingEvents`：每条句子的停留记录，继续保存 `noteId`、`startedAt`、`endedAt`、`durationMs`、`source`、`dateKey`。

服务端写入时会做轻量校验：根对象必须是对象；四个数组字段不存在时补为空数组；设置字段不存在时补为空对象；不接受超过大小限制的请求。

## API 设计

为了保持简单，第一版使用少量批量接口：

- `GET /`：返回 `index.html`。
- `GET /api/health`：返回服务状态、局域网地址提示、数据更新时间。
- `GET /api/state`：返回完整共享状态。
- `PUT /api/state`：保存完整共享状态，用于迁移或批量覆盖。
- `POST /api/notes`：批量新增或更新句子。
- `DELETE /api/notes/:id`：删除单条句子。
- `POST /api/settings`：更新设置。
- `POST /api/fonts`：批量新增或更新字体。
- `DELETE /api/fonts/:id`：删除字体。
- `POST /api/reading-events`：批量追加阅读事件。
- `POST /api/clear-notes`：清空句子库，保留设置、字体和阅读记录。

阅读事件采用追加写入。句子、字体和设置采用按 `id` 或 `key` 覆盖更新。每次写入都会更新 `updatedAt`，并原子写入到 `sync-data.json`，降低断电或中途退出导致文件损坏的概率。

## 前端存储适配

在 `index.html` 内新增一个存储适配层，统一封装当前的 IndexedDB 操作和远程 API 操作。

推荐接口：

```js
const storage = {
  mode: "local" | "lan",
  loadAll(),
  saveNotes(notes),
  saveSettings(settings),
  saveFonts(fonts),
  appendReadingEvents(events),
  deleteNote(id),
  deleteFont(id),
  clearNotes()
};
```

应用内部尽量调用 `storage`，减少业务逻辑直接关心 IndexedDB 或 API。这样能保留现有本地模式，也能在局域网模式下复用同一套渲染、随机回顾、句子库管理、字体导入、主题切换和阅读记录逻辑。

## 同步策略

第一版采用“电脑主库 + 设备主动保存”的策略。

- 打开 `http://...:8787/` 时，页面先从 `/api/state` 加载共享数据。
- 用户在任一设备新增、编辑、删除句子，立即写入服务端，再刷新本地内存并重新渲染。
- 用户切换主题、字体、字号、行高，立即写入服务端。
- 阅读停留事件在切换句子、页面隐藏、关闭设置等现有时机提交，同时追加到服务端。
- 页面回到前台时可轻量重新拉取一次 `/api/state`，吸收其他设备最近的变更。

冲突处理保持简单：

- 句子和字体按 `updatedAt` 较新的记录覆盖较旧记录。
- 设置以最后一次保存为准。
- 阅读事件只追加，不互相覆盖。
- 删除句子时不删除历史阅读事件，继续沿用当前设计中的“已删除句子”统计兼容逻辑。

如果两个设备同时编辑同一条句子，最后保存的版本生效。第一版不做逐字段合并，因为读书笔记应用的并发编辑概率较低，复杂冲突 UI 会让体验变重。

## 本地数据迁移

当用户用电脑打开 `http://localhost:8787/`，且浏览器 IndexedDB 中已有本地数据，而服务端 `sync-data.json` 为空时，页面提供“导入本机数据到同步库”按钮。

迁移规则：

- 迁移句子库、显示设置、字体和阅读记录。
- 迁移前显示摘要：句子数量、字体数量、阅读记录数量。
- 用户确认后调用 `PUT /api/state` 覆盖服务端空库。
- 迁移成功后切换到局域网同步数据。
- 本地 IndexedDB 不删除，作为回退备份。

如果服务端已有数据，则不自动覆盖。设置里提供“从本机合并到同步库”的入口，合并按 `id` 和 `updatedAt` 处理，避免误删服务端已有数据。

## UI 设计

主界面增加低干扰同步状态：

- 桌面端：顶部状态区显示“本地模式”或“局域网同步”，同步模式下显示最后同步时间。
- 移动端：状态文字保持短小，例如“同步中”或“本地”。
- 设置抽屉首页增加“同步状态”区域。

同步状态区域包含：

- 当前模式。
- 服务地址，例如 `http://192.168.1.8:8787/`。
- 最近保存时间。
- “刷新同步数据”按钮。
- “导入本机数据到同步库”按钮，仅在合适场景显示。

发生错误时，使用温和提示，不打断阅读：

- 手机未连到电脑服务：提示“同步服务暂时不可用，请确认电脑端服务仍在运行，并且两台设备在同一 Wi-Fi。”
- 保存失败：保留当前页面数据，并提示用户稍后刷新或重新启动同步服务。
- 文件过大：提示用户删除过大的字体文件或清理数据后重试。

## 安全与边界

该方案只面向可信局域网。服务不开放公网访问，不做账号密码系统。

服务端默认监听 `0.0.0.0:8787`，让手机可以访问。启动提示中明确说明：

- 仅在家庭、办公室等可信网络中使用。
- 不要在公共 Wi-Fi 中长时间开启。
- 使用完可以关闭命令窗口结束同步服务。

服务端限制：

- 只服务当前目录下的 `index.html` 和必要 API。
- 不提供任意文件浏览。
- 请求体大小设置上限，避免误传超大文件。
- 写入 JSON 前做基础结构校验。

## 错误处理

- `sync-data.json` 不存在：自动创建空库。
- `sync-data.json` 损坏：保留损坏文件为 `.broken-时间戳`，创建新的空库，并在页面提示用户。
- 端口被占用：启动脚本提示用户关闭占用程序，或改用备选端口。
- 手机访问失败：启动脚本显示电脑可用局域网 IP，用户优先尝试同一 Wi-Fi 下的 IPv4 地址。
- API 保存失败：页面保留当前内存数据，不显示“已同步”，并提供重试入口。

## 测试计划

- 语法检查：检查 `index.html` 内联脚本和 `sync-server.js` 的 JavaScript 语法。
- 本地服务验证：
  - 启动服务后访问 `http://localhost:8787/` 能打开应用。
  - `GET /api/health` 返回正常状态。
  - `GET /api/state` 在空库时返回完整空结构。
- 数据写入验证：
  - CSV 导入后，句子写入 `sync-data.json`。
  - 新增、编辑、删除句子后，刷新页面仍保持正确。
  - 主题、字体设置保存后，另一浏览器打开同步地址能看到一致设置。
  - 阅读停留记录追加写入，统计摘要保持正确。
- 移动端验证：
  - 用浏览器模拟手机尺寸访问局域网模式，主界面布局正常。
  - 左滑上一条、右滑下一条仍可用。
  - 设置抽屉、句子库、阅读记录在移动端不溢出。
- 双端验证：
  - 电脑端新增一句，手机刷新或回到前台后出现。
  - 手机端产生阅读记录，电脑端刷新记录后能看到。
  - 两端先后修改设置时，最后保存的设置生效。
- 回退验证：
  - 直接打开 `file://.../index.html` 仍进入原本本地模式。
  - 无同步服务时，本地 IndexedDB 数据不受影响。

## 实施顺序

1. 新增 `sync-server.js`，完成静态页面服务、状态文件读写、基础 API 和错误处理。
2. 新增 `start-sync.bat`，让用户可以双击启动，并显示手机访问地址。
3. 在 `index.html` 中增加存储适配层，保留 IndexedDB 本地模式并新增 LAN API 模式。
4. 调整现有数据读写路径，让句子库、设置、字体和阅读记录通过适配层保存。
5. 增加同步状态 UI、刷新按钮和本机数据迁移入口。
6. 验证本地模式没有退化，再验证局域网模式下的导入、编辑、字体、主题、阅读记录和移动端手势。

## 风险

- 当前 `index.html` 已经较大，新增同步适配时需要保持函数边界清晰，避免把业务逻辑和网络请求混在一起。
- 本地导入字体以 `dataUrl` 保存，字体文件过大时会让 `sync-data.json` 变大。第一版保留能力，但需要请求体大小限制和错误提示。
- 手机访问电脑服务可能受 Windows 防火墙影响。实现后需要在说明里提示用户允许 Node.js 局域网访问。
- 公共网络中开启局域网服务有隐私风险，因此 UI 和启动脚本都要提醒“只在可信网络使用”。
- 多设备同时编辑同一条句子时，第一版使用最后保存生效，不提供复杂合并界面。
