# 移动端优先界面美化设计

## 背景

当前读书笔记随机回顾应用已经是单文件 HTML 应用，包含 CSV 导入、随机回顾、句子库管理、主题和字体设置、阅读记录、备份恢复、局域网同步、PWA 和 APK 打包。随着功能变多，界面仍保持可用，但在移动端出现几个视觉问题：

- 设置页功能入口变多后，卡片层级偏“堆叠”，缺少统一的信息秩序。
- 阅读卡片、筛选、收藏、同步状态和底部按钮之间的视觉关系还不够精致。
- 夜间主题可用，但还可以更像“夜读书灯”，减少纯黑界面的生硬感。
- 移动端是主要使用场景，需要优先保证 360px、375px、390px、414px 宽度下的阅读和操作舒适度。

用户已选择视觉方向：**A「墨韵纸页」为主，融合 C「夜读剧场」的夜间氛围**。

## 目标

- 以移动端为第一优先级优化整体显示效果，再兼顾桌面端展开。
- 保持“极简、优雅、宁静、纸张质感”的基调，同时提升设计感。
- 阅读页更像高级阅读器：留白更稳、卡片更轻、层次更清楚。
- 导入页更有仪式感，但不变成营销落地页。
- 设置页改成更清楚的“索引册”结构，让句子库、显示设置、阅读记录、备份中心入口更统一。
- 夜间主题升级为温暖、低眩光的“夜读剧场”效果。
- 统一按钮、表单、统计卡、列表卡、图表卡的视觉语言。
- 动效更克制：减少重复动画，保留与操作原因相关的状态过渡。
- 严格避免横向滚动、按钮遮挡、安全区冲突和长句把操作区推得过远。

## 非目标

- 不重写项目架构，不拆分为 React/Vue/多页面工程。
- 不改变 IndexedDB、局域网同步、备份恢复、阅读记录等数据逻辑。
- 不新增大型 UI 框架或第三方动画库。
- 不新增复杂功能；本次只做视觉、布局、响应式和少量交互状态整理。
- 不把界面改成花哨、强营销或高饱和风格。

## 设计方向

采用“墨韵纸页 + 夜读书灯”的视觉系统。

白天主题：

- 背景保留纸张色，但改成更细的纹理和更浅的纸网格。
- 阅读卡片像轻薄纸页，不做厚重玻璃卡。
- 主色继续使用低饱和青绿，少量陶土色用于提示和危险操作。
- 阴影变得更柔和、更靠近自然纸张悬浮。

夜间主题：

- 不使用纯黑大面积背景，改成深墨绿/炭黑。
- 增加温暖琥珀色作为低亮度强调色，模拟书灯照明。
- 卡片表面保留细边框和微光，不使用强烈霓虹或高对比发光。
- 文字对比保证阅读清晰，次要文字不发灰发糊。

## 移动端布局原则

目标尺寸：

- 360px
- 375px
- 390px
- 414px

阅读页：

- `appShell` 使用 `100dvh / 100svh`，保留现有 fallback。
- 顶部状态区改为两行以内的紧凑信息条，避免筛选 chips 与同步文字互相挤压。
- 阅读卡片移动端使用更小圆角、更明确的最大高度：
  - 长句时卡片内部允许滚动。
  - 不让底部按钮被推到很远。
  - 首屏至少能看到阅读卡片主体和核心操作按钮。
- 收藏按钮保持 44px 触控区域，放在卡片右上角，但不压住正文。
- 正文使用 `clamp()`，移动端字号略降，行高保持舒展。
- 底部操作区使用稳定 grid：
  - 第一行：上一条 / 随机回顾 / 下一条。
  - 第二行：计数或范围提示。
  - 固定按钮考虑 `env(safe-area-inset-bottom)`。

设置页：

- 手机端作为底部抽屉，最大高度控制在可视区域内。
- 标题栏保持可见，关闭按钮触控区域不小于 44px。
- 首页入口卡片从“大块列表”变为更紧凑的索引项。
- 二级页面保持返回路径清晰，段落间距比桌面更紧。
- 统计卡在移动端使用两列，小卡片数字更清楚，说明文字更短。

列表页：

- 句子库列表减少单卡高度，正文预览、来源、统计 chips、操作按钮层次更清晰。
- 阅读记录和备份中心的详情展开样式统一，避免每个模块像不同组件拼在一起。
- 图表卡保持可读，柱状图和排行条不因为窄屏挤压文字。

## 组件视觉系统

新增或整理 CSS token：

- `--surface-raised`：主卡片表面。
- `--surface-inset`：输入框、列表内部块。
- `--line-soft`：统一细边框。
- `--shadow-paper`：轻纸页阴影。
- `--shadow-sheet`：设置抽屉阴影。
- `--accent-warm`：夜间书灯强调色。
- `--motion-fast`、`--motion-medium`：统一动效时间。

组件规则：

- 主要按钮：深墨底色，移动端高度不低于 48px。
- 次要按钮：浅表面 + 细边框，避免过多实心按钮竞争。
- 危险按钮：陶土色边框和文字，远离主要操作。
- 输入框：统一圆角、内边距、focus ring。
- 统计卡：用小标题、主数字、短说明三层结构。
- 设置入口卡：左侧文本、右侧轻箭头，减少装饰。
- 阅读卡片：正文优先，视觉装饰只做低透明引用符和纸页边界。

结构性图标：

- 尽量减少 emoji 作为功能图标。
- 设置、收藏、上一条/下一条等保留清晰文本或轻量符号。
- 随机回顾按钮去除过度装饰，改成更稳定的文字和微动效。

## 动效设计

全局动效原则：

- 动画只表达状态变化，不做纯装饰循环。
- 使用 `transform` 和 `opacity`，避免动画触发布局抖动。
- 时长控制在 160ms 到 360ms。
- 系统开启 `prefers-reduced-motion: reduce` 时，退化为极短淡入或无动画。

具体动效：

- 页面进入：轻微浮现，不做大位移。
- 阅读切换：保留纸页翻动感，但降低旋转和位移强度。
- 设置抽屉：从底部/右侧滑入，带柔和 scrim。
- 按钮按压：轻微压低或色层变化，不移动周围元素。
- 详情展开：使用原生 `details`，视觉上通过边框和背景变化表达展开。

## 页面级改造

### 导入页

- 标题更像书页封面，而不是普通上传页面。
- 上传区域改成轻纸页边框，按钮与说明更精炼。
- 保持第一屏就是导入能力，不做营销 hero。

### 阅读页

- 重新调整状态行、阅读卡、按钮区的垂直节奏。
- 长句卡片内部滚动，底部按钮始终靠近首屏。
- 收藏按钮与范围筛选视觉更轻，不喧宾夺主。
- 夜间主题强化书灯感。

### 设置首页

- 同步状态和当前笔记统计保留，但视觉上更清楚地区分“状态卡”和“导航入口”。
- 功能入口按信息优先级排列：
  - 句子库
  - 显示主题字体
  - 阅读记录
  - 备份与恢复
  - 重新导入 / 清空
- 移动端减少单入口高度。

### 句子库

- 表单和列表卡片统一为轻量纸页块。
- 收藏按钮更轻，编辑/删除按钮保持清晰。
- 长句预览不撑爆卡片，详情展开仍可查看完整内容。

### 阅读记录

- 摘要数字更突出。
- 图表色彩与主题统一。
- 详情列表在移动端高度受控，避免单条记录过长。

### 备份与恢复

- “完整备份”“本地快照”“桌面备份文件”“数据体检”统一为清晰分区。
- 高风险操作的按钮层级更明确。
- 本地快照卡片压缩高度，同时保留恢复/删除操作。

## 可访问性与触控

- 所有核心按钮触控区域不小于 44px。
- 保留可见 focus ring。
- 文本对比满足阅读需求，夜间主题单独检查。
- 不依赖颜色表达唯一状态，收藏和当前筛选都有文字或状态属性。
- 移动端不禁用缩放。
- 无横向滚动。

## 文件影响

主要修改：

- `index.html`
  - CSS token、主题变量、移动端媒体查询。
  - 阅读页、导入页、设置页、句子库、阅读记录、备份中心相关 class。
  - 少量 JS 可用于切换更细的视觉状态，但不改变数据逻辑。

可能修改：

- `README.md`
  - 如最终有新的移动端体验说明，再补一小段。
- `docs/superpowers/plans/`
  - 实施计划另写。

不修改：

- `sync-server.js`
- IndexedDB store 结构
- 备份文件结构
- Android / Capacitor 配置

## 验收标准

移动端：

- 360px、375px、390px、414px 宽度下无横向滚动。
- 375px 宽度下，阅读页首屏能看到主要句子卡片的大部分内容和核心操作按钮。
- 长句不会把按钮区推到很远；卡片内部可以自然滚动。
- 设置按钮不被手机浏览器底部工具栏或安全区遮挡。
- 设置页首页一屏能看到更多入口，且层级清楚。
- 句子库、阅读记录、备份中心不出现文字溢出和按钮拥挤。

主题：

- 白天主题更轻、更像纸页。
- 夜间主题更温暖、更沉浸，但文字仍清晰。
- 主题切换后各类卡片、图表、按钮边框都保持可辨识。

动效：

- 阅读切换动画不重复、不混乱。
- 设置抽屉打开关闭顺滑。
- `prefers-reduced-motion` 下没有明显位移旋转。

验证：

- `npm.cmd run verify` 通过。
- `npm.cmd run cap:copy` 通过，保证 APK 打包资源同步。
- 浏览器或 Playwright 检查 360px、375px、390px、414px。

## 风险与缓解

- `index.html` 已经较大，视觉改造容易误碰业务逻辑。
  - 缓解：优先改 CSS 和 HTML class，JS 只做必要状态整理。
- 新增阴影、纹理和动效可能影响移动端性能。
  - 缓解：不使用大面积 blur，不做循环动画，动效只用 transform/opacity。
- 夜间主题改动可能影响已有主题变量。
  - 缓解：通过语义 token 层改，不在每个组件硬编码颜色。
- 设置页功能多，移动端仍可能拥挤。
  - 缓解：压缩入口高度，统一小卡片，详情内容保留在二级页面。
